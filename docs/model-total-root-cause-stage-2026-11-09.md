## 先定义需要解释的现象

- 误差统一为预测总分减实际全场总分；负值表示低估。核对是否包含加时，不能混用 48 分钟标签和全场标签。
- 相对盘口偏低单独报告，不作为真实预测误差或证明盘口正确的依据。
- 固定比赛清单和排除原因，报告 n、实际均值、预测均值、平均偏差、MAE、RMSE、低估比例、异常拦截和缺失数；XGB／MLP 分开。
- 按 NBA 比赛日分组估计偏差区间，说明小样本限制。预设时间范围、开季／数据缺口等赛前可定义切片，不根据结果挑选低估比赛。
- 按实际总分筛选的高分尾部仅作事后描述，不能直接证明可部署系统偏差。先区分全体持续负偏差、特定时期偏差和正常回归不确定性。

## 修复前必须达到的证据标准

每个可疑原因单独填写以下项目：

1. **事实**：具体字段／代码／模型文件／版本，以及可复现输入和预期含义；区分已知错误和猜测。
2. **连接**：该因素如何影响总分、方向及分数大小。发现代码错误不等于它导致本次总分低估；MLP 原因不能解释成 XGB 原因。
3. **对照**：同一批固定样本，隔离改变该因素，其余保持不变；保存原始输出、影响分布及负对照。涉及当时未知信息时只作为数值诊断。
4. **反证与限制**：无此因素时是否仍然低估，机制不能解释哪些比赛；不把 SHAP、相关性、单场改高或平均值靠近盘口视为因果证明。
5. **复核**：确定性问题核对计算规范和受影响路径；统计假设使用未参与该假设选择的后续证据或预先锁定验证，报告不确定性及 MAE／尾部副作用。样本不足明确保留结论。

证据状态固定分为“待检验”“不支持”“确定性机制已复现”“支持但效果待验证”“证据不足”。不将已复现的工程机制写成已证明修复会提升预测准确率。

达到证据标准后，先交付归因报告和有针对性的修复范围，再进入对应修复工作；不能在调查中顺手修改生产路径。修改权重／训练策略仍遵守原发布准入，不能为结束本阶段降低门槛。连续 200 场是模型发布要求，不是开始根因调查的前置条件。
