## 建议锁定的下一阶段目标

自动产生可信赛前预测、赛后结算和误差数据库，作为后续优化依据。先完善记录／评估，不以每场输赢即时改变权重，不自动跳过发布准入。不扩展模型搜索。

### A. 明确线上模型和统计口径

- 修复包独立上线流程，使用修复版本和合同；XGB 取证不作为前置依赖。保持原权重和可回滚镜像，旧协议留档冻结，修复后记录使用新协议。
- 历史准确率仅统计可核验真实赛前记录：精确开球时间、created_at/as_of 早于开球、训练截止早于目标比赛日、结果 Final 且比分完整。预览、重建、训练内、测试记录单独列出。
- 不删除原两条旧结果，但不混入正式成绩。无有效样本显示“暂无有效赛前样本”；所有百分比展示分子／分母、模型／版本、时间范围、待结算／缺失／拦截数。
- 胜负准确率不能替代分差／总分 MAE、RMSE、平均偏差；没有当时保存的真实盘口不计算大小分或赢盘命中率。

### B. 自动预测留档

- 新赛程入库／更新时间后，后台任务按 game_id 和真实主客队生成一次“赛程发现阶段”预测，保存当时信息。这个阶段与 T-60 分开统计，不能混合不同预测时距。
- 固定 T-60..T-50 窗口再采一份“赛前阶段”记录；已开始／结束、没有精确开球时间或训练覆盖目标标签时不新建赛前记录。
- 各模型独立保存：生产 XGB、明确版本的 MLP、已锁定影子总分；原始输出、最终输出、异常原因均保留，不只留推荐结果，也不只留成功模型。
- 记录 game_id、NBA 比赛日、开球时间、actual server as_of／创建时间、阶段、模型包及代码哈希、合同、模型原始／最终输出、有序特征和实际预处理快照、伤病来源／质量、数据修订、原始盘口与观察时间。
- 唯一键按比赛＋模型包＋阶段／协议；并发重试幂等，预测不可变；赛程改期保存修订，不覆盖旧预测或回填过去时间。错过采集窗口必须计入缺失覆盖率。

### C. 赛后自动对比

- 比分采集提交 Final 后触发结算；另设定时兜底处理遗漏。比分完整即可评估赛果，球队／球员统计缺口另外标注，不能伪装为完整。
- 原预测不变；结算按模型、版本、阶段独立保存实际主客得分、胜负、分差／总分、带符号误差和绝对误差、Brier／log loss 所需信息。
- 赛果修正应保留结算修订和来源，再更新统计，不能改写赛前预测。相同 Final 多次采集不产生重复结算。
- Dashboard 读取同一套权威数据库记录，不混淆旧 predictions、文件影子记录与新自动队列；旧文件可保留原时间／协议按明确导入规则处理，不能冒称新正式前瞻记录。

### D. 优化反馈

- 先按固定样本窗口定期生成诊断报告，包含样本数、覆盖率、负偏差、异常拦截、按比赛日的不确定性，以及版本／时距对照。
- 有足够数据或稳定漂移证据时，生成可审查的优化任务；单场错误不直接修改模型，胜负 100% 也不停止总分误差监控。
- 若之后允许自动训练，只能后台训练独立候选，遵守固定规则和历史／前瞻准入；生产包不因训练结束自动切换。
- Docker 停机无法采集。服务健康、最后成功采集时间、错过窗口数应可见，不能用赛后重建掩盖停机空白。

## 必须验证的验收用例

1. 新赛程入库产生记录，主客绑定正确；重复触发不重复保存。
2. 赛后不能新建“赛前”预测；未知精确时间只能留预览状态。
3. Final 到达能自动结算，重复 Final 幂等，赛果修正有版本，原预测不变。
4. 旧两条假设预览不进入正式准确率；0 个有效样本不显示 100% 或虚假 0% 成绩。
5. 合成两场一对一错时显示 1/2；总分误差不受胜负正确与否影响。
6. 原 MLP／修复 MLP／XGB 的版本和记录分开，可精确重放，长版本 ID 不截断。
7. 输出被拦截或某个模型失败时仍保存失败事实，不造成成功样本选择偏差。
8. 新闭环不改旧影子协议，不把手动诊断／历史重建算入正式 200 场。

本文件是证据基础上的实施设计，不声称自动闭环已经新增部署或 MLP 修复已经上线。
