# 旧 MLP 常量坐标兼容修复与验证（2026-11-10）

本轮按用户要求，只修复已由 11 月 9 日根因报告证实的 MLP 问题。不扩展模型搜索、不重训，XGB 取证独立保留，未成为本轮实现或验证的前置条件。

## 修复实现

新增 `ml/src/legacy_mlp_compatibility.py`，对固定版本 `20261022_050952` 的确切五个模型／scaler／metadata 文件逐一核对 SHA256。只有显式指定修复合同，或加载包含该合同的 manifest，才启用处理。

在旧 scaler 和原网络之前，将 raw 166 维向量的第 17／50 列（冻结兼容定义下的 home／away_avg_ast_pct）恢复为训练常量 0。其余列、输入 dtype、原权重、BatchNorm、目标逆变换及输出异常拦截保持不变。不把这套规则自动应用于其他版本或 213 维模型。

- 处理使用副本，不修改调用者的原始向量，重复执行幂等。
- 错误维度、非有限数值、被改动的合同、文件或 scaler 均拒绝启用。
- 不设置总分补偿常数或新裁剪下限。
- MLP 三个头共享输入，所以胜率／分差也会改变；本轮对三头做数值一致性检查，不宣称只改变总分。
- 输出版本为 `20261022_050952+legacy_mlp_1022_constant_ast_v1`，数据质量中返回兼容 ID。
- 合同嵌入返回的 release manifest，保存后无需原来本地合同路径即可恢复相同处理；工作区输入快照的模型版本与实际修复版本匹配。

`ml/src/predictor.py` 增加显式 `mlp_compatibility_path` 参数及 manifest 恢复路径。默认加载旧 active.json 仍走旧行为，旧真实诊断协议不被覆盖。未复制整个工作区到线上。

## 固定验证协议

在实验前保存 `reports/mlp_constant_repair_20261110/protocol.json`。固定两列和 0 值，不选新超参数，不根据验证结果扩大通道范围。

采用冻结生产镜像的最小 predictor 覆盖，只加入上述显式兼容入口、返回标识及 manifest 恢复；原 MLP 模块和模型文件保持不变。隔离容器断网、根文件系统和模型卷只读。另验证当前工作区真实快照／重放接口，避免修复后留档无法复现。

## 结果

132 场输入来自 11 月 9 日冻结队列，NBA 比赛日 2026-10-22 至 11 月 8 日。它们是**历史重建诊断，不是真实赛前成绩，也不是新独立测试集**。

| 指标 | 原 MLP | 修复 MLP |
| --- | ---: | ---: |
| 总分平均偏差 | -25.518 | -2.848 |
| 总分 MAE | 27.612 | 15.535 |
| 总分 RMSE | 32.407 | 19.576 |
| 整模型输出拦截 | 21 | 0 |

修复结果与根因报告预先指定的双坐标探针一致，并非新增模型搜索。XGB 三项输出逐场相同，推荐主模型仍为 XGB；MLP 改变可能影响模型一致性与综合置信度，不能声称整份响应一字不变。

工程核验：

- **163 项回归通过**，包括新修复的维度、变更合同、文件篡改、scaler 错位、输入不变和版本隔离测试。
- 原训练缓存抽取 **100 条**，修复前后三个输出最大差 **0**。
- **132 场单场／批量**验证通过；原输入不变，scaler 不被重复应用。
- 原图 PyTorch／ONNX 三头最大差依次为胜率 `1.19e-7`、分差 `4.29e-6`、总分 `1.53e-5`，均满足预设容差。
- 工作区 **132 条实际处理后快照**均可根据保存的 manifest 和修复版本精确重放，未新写数据库预测账本。
- **221 个早期数值探针**，异常拦截由 52 降到 1，新增拦截 0。剩余一条为 2021-01-01 的 `22000073`，仍产生越界输出并被原 guard 拦截。没有为它放宽 guard 或扩大本轮修复。
- 两个坐标分别设为 0、常见值、5 或极大有限值的压力输入，修复后输出一致；其他坐标不被掩盖。

这些检查证明已实现并隔离验证这一兼容修复，不等于新包已经通过真实前瞻精度准入。剩余约 -2.85 分平均偏差没有被解释或继续调参。

## 交付和线上边界

目录 `reports/mlp_constant_repair_20261110/` 包含：

- `contract.json`、`candidate_manifest.json`：固定合同与**未激活**修复包元数据。
- `frozen_predictor_repair.py`：基于冻结服务代码的最小覆盖，避免混入其他工作区改动。
- `final_onnx_validation.json`、`final_pytorch_validation.json`：冻结服务环境与原图数值验证。
- `workspace_snapshot_validation.json`：当前实际快照／重放路径验证。
- `regression_final_163.log`：最终回归记录。
- `repair_source_snapshot.zip`、`artifact_checksums.json`、`continuation_checkpoint.json`：代码交付、哈希和接续状态。

使用隔离修复 manifest 的入口为 `load_predictor(release_manifest=repair_manifest)`；或显式 `load_predictor(mlp_compatibility_path=contract_path)`。未配置时不自动改变旧包。合同只适用于原确切权重；更换任意被锁定文件后会拒绝使用。

**生产 active.json、原模型文件、线上容器、既有真实诊断协议与记录均未切换或改写。** 修复工程交付不等待 XGB 取证；正式激活是独立发布步骤，继续遵守此前锁定的准入，不能把重建结果当成 200 场正式成绩。若上线该修复，必须使用带独立标识和合同的版本，重新锁定对应采集协议，不能把新行为混入旧 MLP 留档。

首次隔离验证发现包装器将 float32 输入转为 float64，造成原训练输入舍入差。已修正为保留 dtype，随后验证训练输出完全不变。另补齐了保存 manifest 后恢复兼容处理及快照版本一致性，最终三条验证路径均通过；旧中间验证输出独立保留，不覆盖原研究报告。

下一步若进入发布工作，只围绕此固定修复做独立正式留档及发布验收；XGB 根因调查不阻塞这一修复的工程交付，也不随本轮新增研究候选。
