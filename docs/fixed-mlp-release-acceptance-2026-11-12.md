## 正式切换顺序与尚未执行的事项

模型包层验收通过不等于已完成整站生产切换。正式部署必须执行以下顺序：

1. **先安排旧影子采集环境隔离。** 原总分、胜负、旧配对及新 MLP 安全观察协议都固定了旧选择器和／或运行代码。不能直接改 `active.json` 后指望旧协议继续匹配，更不能改旧协议内容。需保留相应旧镜像、固定旧基线选择器作为独立采集环境，再切主 API；总分自动采集尤其依赖后端调度器，不能只处理两个独立观察器。本轮未执行这项整站调度拆分，也未认证切换后的影子连续性。
2. 在旧服务仍可运行时，将生产迁移至 010，仅扩字段，保留全部数据；旧镜像兼容性已经验证。生产目前仍为 009。
3. 部署已验收的兼容镜像，保持旧选择器，先验证健康、接口与伤病绑定。**不能先切选择器再部署代码**：旧推理代码不理解修复合同，可能仍返回旧行为。
4. 将已校验候选包安装到不可变的新目录；用专用 CLI validate，再 activate。执行环境必须指向生产模型目录，且保留原包与原代码镜像。
5. 验证实际响应中的完整 MLP 行为版本、XGB 版本不变、当前输入留档和重放；继续真实错误／拦截监测，不让发布脚本自动训练。

如需回退：**先用兼容代码将选择器恢复旧包，再回退代码镜像**；保留数据库 010，不缩回 20 字符，不删除修复期间的记录。旧镜像可以展示长版本记录，但重放修复记录仍需保留的兼容镜像及归档 manifest，不能用旧算法冒充修复行为。

专用命令形态（此处为运行说明，本轮只在隔离副本执行）：

```text
python scripts/fixed_mlp_release.py validate --models-dir MODEL_ROOT --package IMMUTABLE_PACKAGE
python scripts/fixed_mlp_release.py activate --models-dir MODEL_ROOT --package IMMUTABLE_PACKAGE
python scripts/fixed_mlp_release.py rollback --models-dir MODEL_ROOT --package IMMUTABLE_PACKAGE
```

专用发布路径与数据库保护的代码已交付；生产安装、迁移、观察器隔离和实际切换未执行。剩余工作属于部署编排，不是重新等待 200 场或继续模型搜索。
