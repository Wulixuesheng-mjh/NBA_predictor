## 一、今日工作总结

### 1. Docker 数据迁移（承接上次会话）

**问题**：C 盘从 48GB 剩余降至 18GB，根因是 `docker_data.vhdx` 虚拟磁盘文件膨胀至 37.7GB（实际数据仅 ~4GB）。

**过程**：
- 尝试了 5 种 VHDX 压缩方法（`diskpart compact`、`Optimize-VHD`、`convertvhd`、`wsl --mount` + `fstrim`、导出导入），均无法显著压缩
- **根因**：VHDX 内部的 ext4 文件系统碎片化，TRIM/DISCARD 命令无法从 WSL 层穿透到 NTFS 上的 VHDX 文件
- **最终方案**：将 Docker 数据从 C 盘迁移到 E 盘

**迁移步骤**：
1. 停止 Docker Desktop + WSL
2. `robocopy` 将 `C:\Users\...\AppData\Local\Docker` 复制到 `E:\DockerData`
3. 在原位置创建 NTFS 目录联结 (`mklink /J`)，让 Docker Desktop 仍能通过原路径访问数据
4. 修复 E 盘 NTFS 权限（`icacls` 授予当前用户完全控制权）
5. 修复 Docker Desktop 快捷方式

**结果**：C 盘释放 ~29GB，Docker Desktop 恢复正常。

### 4. 前端 307 重定向修复

**问题**：前端通过 nginx 代理调用后端 API 时，FastAPI 对无尾部斜杠的 URL 返回 307 重定向，但重定向 `Location` 头丢失了端口号（`localhost` 而非 `localhost:3000`）。

**根因**：
```
请求: GET /api/v1/teams (localhost:3000)
→ Nginx 代理到 backend:8000
→ FastAPI 返回 307 Location: http://localhost/api/v1/teams/  ← 缺少 :3000
→ 浏览器跟随到 localhost:80 → 失败
```

**修复**：在 nginx 配置中添加 `proxy_redirect` 指令重写重定向 URL：
```nginx
proxy_redirect http://localhost/ http://$host:3000/;
```

**验证**：预测端点通过前端代理正常返回结果（湖人 vs 勇士：53% 主胜）。
