## 2. 旧 MLP 的可定位问题

原 MLP 的 scaler 存在，目标反标准化代码存在。总分训练目标均值约 225.575、标准差约 20.137，未发现简单的“忘记还原分数”。eval 模式和 Dropout 状态也正常。

主要发现是输入 BatchNorm 的近零方差通道：按当前归档 166 列兼容映射，涉及 `home/away_avg_ast_pct`、`home/away_games_available`、`same_conference` 和 `same_division`。这些通道的 running variance 约 `7.055e-10`，有效放大系数约 **316.2**。

- 场次可用数通道在探针中可达到约 1,581 的 BN 后绝对值。
- 助攻率通道可达到约 228–230；输入在 scaler 后没有超过 ±5，仍会被下一层 BN 放大，因此单靠现有裁剪不能解决。
- 同联盟／同分区通道具有相同近零方差风险，但本批探针未显著激活，不能把本次偏差单独归因于它们。

221 个离线数值探针中有 52 个触发输出保护阈值。仅在离线将六个近零方差通道中心化，拦截数变为 0。最近训练截止日之后的 93 个输入探针，原始总分均值约 202.621，诊断中心化后约 223.291。此干预没有使用赛果，说明输入数值机制会显著移动预测中心；不是历史真实预测、修复后准确率或可上线方案。

另找到了同期原缓存 `train_99ec73146ff0f31e.npz`，30,665×166，构建时间 2026-10-22 05:47:40 UTC，SHA `cf0ab97b56dcd161440354abdd5a4a6a4cf46d4edf4788fa9c4110ea281d6805`。四个助攻率／联盟分区列在全缓存恒为 0；两个场次可用数列在全缓存存在少量变化，而模型保存的 BN 统计仍接近零。当前更完整的数据进入旧模型，确有训练／推理分布失配风险。

原模型 metadata 和旧缓存未保存原始特征名列表及独立拟合／验证范围。通道名称归因依据归档兼容列序，不能补造原训练 schema 或精确拟合截止日；页面通用 training_data_until 也不能独立证明 MLP 的拟合范围。新研究产物明确保存有序特征名、模型文件、标准化参数及每折拟合／验证范围。

原生产 PyTorch 类、原 model.pt 和原 model.onnx 的跨引擎检查通过：221 个探针的最大差异分别约 `6.56e-7` 胜率、`2.06e-4` 分差、`7.20e-5` 总分；100 个单场／批量 ONNX 对照差异为 0。因此当前证据指向权重与输入分布、归一化的组合问题，并不支持将大幅偏差归因为 ONNX 数值差异。

生产旧包没有被中心化、重新缩放或覆盖。稳定化训练口径在独立研究中使用：无输入 BatchNorm、训练段拟合 scaler、常量特征 mask、训练／推理一致裁剪、准确停止点全量重拟合。

工作区配置中的 `mlp_input_normalization=none` 作用于新训练，不能移除旧 ONNX 图里已经导出的输入 BatchNorm；仅改配置无法修复旧图。需要重训、导出并独立验收新的产物，不能仍以旧版本名声称行为未改变。

## 6. 新发现的窗口口径问题

现有 T1 以实际最新训练比赛定位“当前赛季”。揭幕月过去数据止于上季六月，因而会保留三个完整旧赛季：

- 2023-10：2020–21、2021–22、2022–23。
- 2024-10：2021–22、2022–23、2023–24。

新赛季有比赛后，规则才切到两个完整旧赛季＋当季。这与按目标比赛赛季理解的严格“两完整季＋当季”有区别。共享及总分独立研究都保持同一既有口径以控制变量，没有看结果后修改窗口或追认成另一种策略；本轮没有额外叠加普通训练入口的 `mlp_training_start` 过滤。

后续应优先单独锁定并比较“按预测截止时点确定赛季”的窗口修正，再决定是否继续 MLP 损失或结构研究。该项需要新的协议和对照，不能把本轮 T1 结果改名成修正后的策略结果。
